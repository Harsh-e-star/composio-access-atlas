01 / Research signals

Three patterns that change the roadmap.

Directional findings from the source-reviewed subset, not extrapolated percentages across all 100 apps.

01 · Access beats existence

A public API can still be a non-starter for launch.

Google Ads requires OAuth plus a developer token. LinkedIn Ads and Amazon SP introduce review or registration gates. Integration priority must factor in production access, not only API coverage.

02 · Auth is not a single label

OAuth is the dominant protocol.

23/41 reviewed support an OAuth variant. Mixed modes matter: Linear supports personal keys too; Twilio uses API keys through HTTP Basic.

03 · Don't rebuild everything

MCP or CLI can skip a wrapper.

Firecrawl has first-party MCP; Mermaid CLI and Sherlock are local tools rather than hosted REST APIs. Agent-callable skills can be the correct interface.

Fastest experiments

GitHub · Linear · Firecrawl

Self-serve credentials and usable documented surfaces. Start with sandbox tasks, scope-safe reads, then writes.

Account / scope work

Salesforce · Shopify · Jira

Clear APIs, but meaningful calls require account permissions, tenant authorization, or a store/workspace.

Outreach / licensing

LinkedIn Ads · NotebookLM

Documented review or enterprise access. Record the blocker and avoid expensive speculative implementation.
